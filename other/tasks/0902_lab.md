Каждый студент должен подготовить **защиту проекта**, выполненного в рамках лабораторных работ. Проект должен представлять собой **работающее мобильное приложение**.

| Вариант | Описание | Технология |
|:---|:---|:---|
| **1** | Приложение «Список задач» (To-Do List) с БД и сетью | Android + Compose + Room + Retrofit |
| **2** | Приложение «Заметки» с категориями и поиском | Android + Compose + Room |

### 3.3. Требования к проекту

1. **Функциональность:**
   - Минимум 2 экрана (навигация).
   - Работа с локальной БД (Room).
   - Сетевые запросы (Retrofit) — опционально, но приветствуется.
   - Управление состоянием (StateFlow).
   - Архитектура MVVM.

2. **Качество кода:**
   - KDoc-комментарии для всех классов и функций.
   - Чистый код, соблюдение Kotlin Coding Conventions.
   - Отсутствие дублирования (DRY).

3. **Документация:**
   - README.md (описание проекта, установка, запуск).
   - REPORT.md (рефлексивный отчёт).

```markdown
# Отчёт по проекту

## Информация о студенте
- **ФИО:** Иванов Иван Иванович
- **Группа:** ПИ-301
- **Дата защиты:** 10.12.2026

## Название проекта
«Список задач» — мобильное приложение для управления задачами

## Технологический стек
- **Язык:** Kotlin
- **UI:** Jetpack Compose
- **Архитектура:** MVVM + Clean Architecture
- **База данных:** Room (SQLite)
- **Сеть:** Retrofit + OkHttp
- **Асинхронность:** Coroutines + Flow
- **Навигация:** Navigation Compose
- **Версионный контроль:** Git + GitHub

## Обоснование выбора технологий
Выбрал Android + Kotlin, так как это наиболее зрелая и стабильная экосистема для мобильной разработки. Jetpack Compose позволяет быстро создавать UI с минимальным количеством шаблонного кода. Архитектура MVVM обеспечивает разделение ответственности и упрощает тестирование. Room + Retrofit — стандартный подход для работы с локальными и удалёнными данными.

## Трудности и их решения

### Трудность 1: Организация кеширования
При загрузке данных из сети нужно было сначала показывать кеш из БД, а затем обновлять из сети.

**Решение:** Использовал Flow из Room, который автоматически обновляет UI при изменении данных. При этом в фоне выполнял сетевой запрос и сохранял результат в БД.

### Трудность 2: Обработка ошибок сети
При отсутствии интернета приложение должно показывать понятное сообщение.

**Решение:** Обернул все сетевые запросы в try-catch, добавил состояние errorMessage в ViewModel. UI подписывается на это состояние и показывает Snackbar.

### Трудность 3: Сохранение состояния при повороте
При повороте экрана список задач сбрасывался.

**Решение:** Использовал ViewModel, которая хранит состояние и переживает поворот экрана. Плюс StateFlow обеспечивает реактивное обновление.

## Что нового узнал

1. **Jetpack Compose:** Декларативный подход к созданию UI, использование Modifier, управление состоянием через remember и mutableStateOf.

2. **MVVM + Clean Architecture:** Разделение на слои (Presentation, Domain, Data), использование Use Cases, инкапсуляция бизнес-логики.

3. **Room:** Создание Entity, DAO, Database. Использование корутин для асинхронных операций. Реактивное обновление через Flow.

4. **Retrofit:** Создание интерфейсов API, конвертация JSON в DTO, обработка ошибок.

5. **StateFlow:** Реактивное управление состоянием, подписка UI через collectAsState.

6. **Git:** Регулярные коммиты, работа с ветками, решение конфликтов.
```
